# AgentDDS 产品需求文档

> 状态：原版已由用户确认；本轮按后续确认，将 GUID 统一为会话窗口标识，不再作为每次任务的编号。受理、状态查询和结果反馈要求保留，修订稿待复核。
>
> 本文只说明用户目标、产品行为和验收结果，不规定代码结构、接口字段或设备业务逻辑。

## 1. 产品需求描述

### 1.1 产品故事

设备开发者在各主机部署 AgentDDS，作为设备程序的纯后台底层驱动。设备程序通过它调用本机或局域网其他主机的 Agent、模型和技能；独立桌面程序负责调试和管理。AgentDDS 不开发设备自身业务。

本文的“会话窗口”也可以是上层程序的一段逻辑会话，不要求有可视界面。GUID 用来识别这个窗口，不是某次任务的编号。

### 1.2 产品亮点

- **访问一致**：本机、局域网程序用同一套接口，实例之间也能联动。
- **能力说得清**：可查模型类型、已支持操作、技能用途和参数模板。
- **目标可控**：指定目标优先，是否自动查找由本机决定。
- **结果可追踪**：状态和结果回到对应窗口，各次调用的反馈不混淆，不把受理当成成功。
- **对话可继续**：不必逐轮重发历史；长期记录仍由调用方保存。
- **管理独立**：后台未运行也能打开桌面程序，管理本机或远端实例。

### 1.3 要解决的问题

以下是需要解决的使用问题，不据此推断现有系统的实现或性能。

- 不清楚哪台主机有什么能力 → 按实例查询；即使模型同名，也能区分目标、类型和支持操作。
- 功能只有名称，不知道怎么调用 → 每项功能提供用途说明和 JSON 参数模板。
- 本机与其他设备要访问同一能力 → 统一接入方式，AgentDDS 也能向对端发起调用。
- 模型任务不一定立即完成 → 先确认受理，再持续提供状态和结果。
- 后台能力需要调试和管理 → 用独立桌面程序查看能力、调试功能、管理当前会话及实例。

## 2. 功能描述

### 2.1 软件

#### 2.1.1 需求描述

本节是功能索引，具体规则和异常验收见对应模块。

| 能力 | 整体要求 | 详细规则 |
| --- | --- | --- |
| 后台与接入 | 单主机单实例；本机和局域网程序统一通过 Zenoh 访问；初始化完成后发布就绪 | §2.2.1 |
| Agent 与对话 | 可调用 Agent；Agent 和大语言保持当前上下文，不混用不同请求方的会话 | §2.2.2 |
| 三类模型 | 提供大语言、图片、视频的已核实操作；不把模型类型当作操作支持证明 | §2.2.3 |
| 任务反馈 | 用请求方的窗口 GUID 关联反馈，区分已受理、处理中、成功和失败；不要求每次生成任务 GUID，重启不恢复旧任务 | §2.2.4 |
| 跨实例查找 | 指定目标优先；自动查找默认关闭，只能本地修改；受理后失败不改选、不重做 | §2.2.5 |
| 技能与能力查询 | 每项公开功能有独立 SKILL 和模板；本机查询与局域网查找是两项不同技能 | §2.2.5–2.2.6 |
| 桌面管理 | 独立、非网页；默认本机，可输入 IP 管理远端；本机可启停，远端仅能重启运行中实例 | §2.2.7 |
| 第一版访问范围 | 不做身份认证或授权，但本机专属操作不因此向远端开放 | §3 |

#### 2.1.2 操作流程

**能力调用：**

1. AgentDDS 初始化完成，通过 Zenoh 表明就绪。本机能力查询 SKILL 提供本实例能力 JSON。
2. 调用方指定目标时优先使用该目标。仅在本机自动查找开启的情况下，遇到未指定目标或指定目标未能受理，才自动执行局域网能力查找 SKILL。
3. 查找逐个调用对端的本机能力查询 SKILL，找到首个匹配即返回目标；发起端先订阅状态，再申请原业务任务。对端不继续替本次请求查找。
4. 请求方携带窗口 GUID 发起调用；同一窗口的后续请求沿用该 GUID。需要会话执行时，存在则复用，不存在则新建，不额外发送新建标识。
5. Agent 调用返回实际结果；三类模型先确认受理，再通过 Zenoh 提供状态和结果，反馈携带原窗口 GUID。已受理任务失败直接反馈，不改选、不重做。
6. Agent／大语言可继续当前对话，也可主动结束；重启后旧会话和任务失效。调用方之后再用相同 GUID 发来新请求，也只是创建新的上下文，不恢复旧业务。

**桌面管理：**

独立打开桌面程序 → 默认连接本机，或输入远端 IP → 查看能力、调试模型／技能、查看或结束当前会话。本机启动、整体关闭、重启及远程重启的条件见 §2.2.7；桌面程序不依赖后台已运行。

#### 2.1.3 验收标准

以下检查完整使用流程，详细条件和异常见模块验收。

- **本机与跨主机调用**：本机和局域网程序分别发现并调用同一实例 → 使用同一套接口，取得结果或如实反馈失败。（§2.2.1–2.2.2）
- **按说明调用**：先查能力，再请求对应功能 → 只列目标实例真实可用能力，说明与实际调用一致。（§2.2.3、§2.2.6）
- **选择目标**：指定目标或按开关自动查找 → 指定优先，仅满足条件才查找；匹配后先订阅再申请，无匹配则失败。（§2.2.5）
- **会话隔离**：多个请求方持续对话，再结束或失活 → 上下文不混用，只清理对应会话、记录和子任务。（§2.2.2）
- **模型任务**：在同一窗口提交多次模型调用并查结果 → 沿用窗口 GUID，先确认受理，正确区分各次调用的状态与结果；失败不重做，重启不恢复。（§2.2.4）
- **桌面管理**：连接本机或远端并操作 → 只作用于当前连接实例；本机整体关闭后桌面仍运行，远端不能启停。（§2.2.7）
- **重启反馈**：分别检查重启成功与未能就绪的情况 → 成功后重新连接，旧会话和任务失效；受理或失败不误报成功。（§2.2.7）
- **接入与验证范围**：接入多个中转站，并核查模型验证结果 → 可完成多中转站接入，故障时不要求自动切换；真实与非真实验证明确区分。（§2.2.1、§2.2.3）

### 2.2 模块

以下按产品功能分组，不表示代码或进程划分；所列功能与验收均为第一版必须项。

#### 2.2.1 实例接入与发现

##### 2.2.1.1 功能描述

- **部署**：每台主机部署一个对外服务实例，不允许两个实例同时对外服务。
- **接入**：本机程序、其他局域网程序和 AgentDDS 均通过同一套 Zenoh 接口访问；第一版不要求互联网访问。
- **就绪**：初始化或重启完成 → 通过 Zenoh 表明本次就绪，调用方能区分重启前后的会话和任务。未就绪不报可服务。
- **发现与查询**：调用方可发现目标 Agent，再调用该实例的本机能力查询 SKILL 获取 JSON。每个实例只报告自身能力；自动查找对端遵循 §2.2.5。
- **多中转站**：支持接入多个 Zenoh 中转站。所需中转站不可用、调用无法完成 → 反馈失败，不要求自动切换。

##### 2.2.1.2 模块验收标准

- **单实例**：同机尝试再部署实例 → 不出现两个同时对外服务的实例。
- **本机与跨主机发现**：本机和另一局域网设备分别接入 → 均可发现和访问所选 Agent，不要求另一套本机专用接口。
- **本机查找对端**：开启本机自动查找，并提交符合查找条件的需求 → 逐个读取对端能力 JSON，不把对端能力当成本机能力。
- **就绪通知**：订阅目标就绪状态，再初始化或重启 → 可获知本次就绪，旧会话和任务不能继续使用。
- **多中转站可用**：配置多个可用中转站 → 仍可完成发现与调用。
- **目标或中转站不可达**：发起无法完成的调用 → 反馈失败，不误报成功，也不要求自动故障切换。

#### 2.2.2 Agent 功能调用

##### 2.2.2.1 功能描述

本机、局域网程序或其他 AgentDDS 发起 Agent 调用 → 返回结果；不能完成则反馈失败。本产品不规定 Agent 的具体执行逻辑。

本机 AgentDDS 也可向对端发送申请、取得状态和结果。对端只执行自身能力，沿用原请求方的存活、会话结束和任务状态规则。

**窗口标识：**请求方提供 GUID，同一窗口的多次请求沿用它。需要会话执行的调用，按 GUID 查找，存在则复用，不存在则新建；不因 GUID 重复拒绝后续请求，不要求为每次调用再提供一个任务 GUID。

**Agent 和大语言共用以下会话规则：**

- **继续对话**：同一请求方继续当前对话 → 沿用上下文，无需逐轮重发完整历史；不同请求方互不混用。
- **主动结束**：请求方显式结束 → 立即关闭对应会话及其子任务，取消待处理请求并清理记录，不影响其他请求方。
- **标记消失**：请求方维护存活标记。实例观察到标记消失 → 等待 1 分钟：
  - 期间恢复 → 保留原会话。
  - 满 1 分钟仍未恢复 → 关闭对应会话和子任务、清理记录，不影响其他请求方。
  - 不依赖定期心跳消息；从观察到标记消失起算，不按消息闲置时间计时。
- **实例重启**：旧会话失效、记录不保留，未完成和待处理请求不恢复。之后相同 GUID 的新调用也会创建全新会话，AgentDDS 不自动重发旧请求。

长期历史由调用方保存；AgentDDS 不提供长期历史的保存、查询或管理功能。

##### 2.2.2.2 模块验收标准

- **本机或跨实例调用**：调用可用 Agent → 收到结果；跨实例时本机不必实现对端设备业务。
- **调用失败**：目标不可用或任务不能完成 → 收到失败，而非成功。
- **窗口 GUID 复用**：同一窗口连续发送多条请求 → GUID 不变，继续对应会话，不当成重复任务拒绝；没有对应会话时自动创建，不要求额外创建标识。
- **连续对话与隔离**：多个请求方分别继续对话 → 各自沿用上下文，不必重发完整历史，也不串用对话。
- **主动结束**：结束其中一段会话 → 立即清理其记录、执行中子任务和待处理请求，其他会话仍可用。
- **失活后恢复**：观察到标记消失后，1 分钟内恢复 → 原会话保留。
- **持续失活**：观察到标记消失后，满 1 分钟仍未恢复 → 清理对应会话、记录、子任务和待处理请求，不影响其他请求方。
- **重启后对话**：调用方用相同 GUID 发送新请求 → 创建全新会话，原上下文和旧任务不恢复；没有新请求时不自动重建对话。
- **长期历史**：调用方需要长期历史 → 自行保存；AgentDDS 不提供其查询或管理。

#### 2.2.3 模型清单与调用

##### 2.2.3.1 功能描述

- **查询模型**：单独查询返回本实例的模型和类型；本机能力查询 JSON 另含已核实操作，二者模型清单一致。不同实例可有同名模型，调用时仍须区分所属实例。
- **调用模型**：优先使用指定实例、模型和操作；需要自动寻找目标时按 §2.2.5 处理，不以其他操作的结果冒充所请求的结果。
- **支持范围**：只提供实际后端已核实的操作，不支持便明确反馈。视频以 MiniMax H3 兼容操作为目标，本地后端不能照搬云端能力；其他示例型号不是必选名单。不要求三类模型共用 OpenAI 兼容接口。

三类模型的对话和验证边界如下：

| 类型 | 输入与对话 | 本版验证要求 |
| --- | --- | --- |
| 大语言 | 可继续当前上下文，无需每轮重发完整历史；结束与失活按 §2.2.2 处理 | 完成真实调用验证 |
| 图片 | 模型只处理本次调用输入，不维护聊天历史；窗口 GUID 用于反馈归属，不改变模型的输入方式 | 完成真实调用验证 |
| 视频 | 模型只处理本次调用输入，不维护聊天历史；结果可晚于受理完成，仍需提供状态和结果并归到对应窗口 | 先完成非真实模型验证，真实调用留待后续 |

以上是验收要求，不表示当前已验证；未执行的真实调用不得标为已通过。

##### 2.2.3.2 模块验收标准

- **模型清单与类型**：查询模型清单和本机能力 JSON → 前者仅列本实例模型并标明类型；后者模型清单一致，并标明已核实操作。
- **同名模型**：在两个实例接入同名模型后分别查询、调用 → 各自列出，按所选实例执行。
- **支持的操作**：指定已支持操作，或按已开启的自动查找命中能力 → 可提交任务并取得状态和结果。
- **不支持的操作**：请求未支持操作 → 自动查找关闭时明确反馈不支持；开启且满足受理前条件时可寻找匹配能力，不以其他操作冒充。
- **指定模型不可用**：分别在受理前、受理后遇到失败 → 前者按自动查找规则处理；后者不换模型、目标或操作，不重做。
- **大语言继续对话**：提交后续任务 → 沿用当前上下文，不要求重发完整历史。
- **图片与视频无模型聊天记录**：分别提交两类任务 → 模型只处理本次输入，不因窗口 GUID 而要求媒体模型维护聊天历史，反馈仍归到对应窗口。
- **真实验证范围**：核查验证结果 → 大语言与图片的真实调用结果可验证；视频仅做非真实验证时，真实调用记为待验证。

#### 2.2.4 模型任务与状态反馈

##### 2.2.4.1 功能描述

三类模型任务统一遵循以下规则：

1. **提交**：请求方提供窗口 GUID，AgentDDS 不代生成。同一 GUID 可以提交多次调用，不要求每次提供新的任务 GUID。所需操作不支持，且（自动查找关闭或按规则仍无匹配目标） → 受理前明确拒绝，不伪装成执行中任务。
2. **受理**：先确认本次调用已受理，再通过 Zenoh 提供状态和结果；反馈携带原窗口 GUID，不将它当作该次调用的唯一编号。
3. **反馈**：至少区分“已受理、处理中、成功、失败”，同一窗口中各次调用的反馈不能混淆。受理不等于成功，不捏造进度百分比，也不把处理中或失败报为成功。单次调用如何关联回执和查询，由技术方案确定，不额外要求调用方生成任务 GUID。
4. **失败**：已受理的某次调用失败 → 如实反馈该次失败；即使自动查找开启，也不换目标、不重新申请或重做。后续同 GUID 的新请求不是旧任务重做。
5. **重启**：旧会话、旧执行状态和待处理请求失效，不跨重启恢复或自动重发。窗口 GUID 可以用于新的请求，但不恢复原上下文和执行结果。

##### 2.2.4.2 模块验收标准

- **三类任务受理**：分别提交三类任务和窗口 GUID → 先收到受理确认，再能通过 Zenoh 订阅或查询；反馈关联原窗口，不要求逐次生成任务 GUID。
- **状态与结果**：同一 GUID 提交多次调用并观察四类状态 → 正确区分各次调用的受理、处理、成功和失败，取得可用结果；不能仅凭 GUID 相同就认为是同一任务，无可靠进度时不显示编造百分比。
- **不支持的请求**：提交不支持且不能按规则找到目标的请求 → 受理前明确拒绝，不产生虚假的执行中状态。
- **执行失败**：查看已受理后失败的调用 → 对应窗口收到真实失败，不误当作其他调用的结果；开关开启也不换目标或重新提交。
- **实例重启**：查询旧执行状态 → 不恢复或重发旧任务；随后相同窗口 GUID 的新调用按新会话处理，不带回旧历史。

#### 2.2.5 跨实例能力查找与联动

##### 2.2.5.1 功能描述

“局域网能力查找”是独立 SKILL，使用各实例的“本机能力查询”结果寻找目标。以下开关条件限定业务调用的自动查找，不在本轮扩展显式调用查找技能的策略。

**开关规则：**默认关闭；仅本机宿主设备程序或同机桌面程序可修改。不通过 Zenoh 对外开放修改能力，也不要求每次调用传入开关。

**一次业务调用按以下条件处理：**

1. 指定了实例、Agent 或模型功能 → 先尝试指定目标。
2. 开关关闭时，若未指定目标或指定目标不能受理 → 反馈失败，不自行选择其他目标。
3. 开关开启时，若未指定目标或指定目标未能受理 → 本机执行局域网能力查找 SKILL，逐个调用可访问实例的本机能力查询 SKILL；首个匹配即返回目标，找不到则反馈无法完成。
4. 查找返回匹配目标 → 发起端先订阅对端状态，再申请原业务任务。查找技能不直接执行命中的业务；对端只提供自身能力，不继续替本次请求查找其他目标。
5. 原任务已受理后失败 → 直接反馈，不改选、不重做。对端重启 → 原会话和任务失效，本机向上层反馈失败，不恢复或重发旧请求。

不代上层保存长期会话或任务记录，也无需维护长期全局能力清单。

##### 2.2.5.2 模块验收标准

- **默认关闭**：不指定目标，或指定目标不能受理 → 不自动查找或改选，反馈无法完成。
- **本机可改、远端不可改**：分别从本机宿主、同机桌面和另一主机修改开关 → 前两者可改，另一主机不能经 Zenoh 修改。
- **开启后无指定目标**：提交未指定目标的需求 → 逐个查询对端本机能力，首个匹配即选定，先订阅再申请并取得状态或结果。
- **指定目标受理前失败**：开关开启时指定不能受理的目标 → 先尝试它，再查找匹配目标并调用；对端不继续查找。
- **受理后失败**：原任务受理后执行失败 → 直接反馈，不再查询其他实例以重新执行。
- **无匹配能力**：查找不到匹配目标 → 返回无法完成，不把不匹配能力报为成功。
- **对端重启**：调用中的对端重启 → 原会话和任务失效，本机向上层反馈失败，不恢复或重发旧请求。

#### 2.2.6 本机 SKILL 与能力查询

##### 2.2.6.1 功能描述

每项对外功能（含 AgentDDS 自身功能）都须有 Codex 可加载的独立 SKILL，说明用途并提供 JSON 调用参数模板。不能用一段笼统说明代替各技能，也不能缺少模板仍宣称可调用。

两项查询／查找技能各有自己的说明和模板：

| 技能 | 用途与结果 | 边界 |
| --- | --- | --- |
| 本机能力查询 | 向本机或其他调用方返回本实例能力 JSON：模型、类型、已核实操作，以及技能用途和参数模板 | 只查询自身，不汇总其他主机；模型类型不能被一段技能描述代替 |
| 局域网能力查找 | 依据对端本机能力查询结果，寻找并返回匹配目标 | 按 §2.2.5 处理，不与本机查询混用职责 |

“本机能力查询”承接原“能力总结 SKILL”，不另加第三个技能。

调用方按已公布操作或技能模板请求功能 → 应与说明一致；未配置、不可用或不支持时如实反馈，不公布不存在的能力。

##### 2.2.6.2 模块验收标准

- **独立技能说明**：分别查询至少两个功能，含 AgentDDS 自身功能 → 每项都有独立用途说明和 JSON 参数模板。
- **两项技能区分**：查询本机能力查询与局域网能力查找的说明 → 可区分用途和输入，不存在重复的第三项“能力总结”技能。
- **本机能力 JSON**：调用本机能力查询 → 只返回本实例可开放模型、类型、已核实操作和技能用途、模板，与实际模型清单一致。
- **同名模型与技能**：查询、调用不同实例的同名能力 → 查询结果只代表自身，调用仍能区分目标实例。
- **能力变化或缺失**：检查未配置、不可用、不支持或缺少模板的能力 → 不被宣称可调用；不支持的请求明确失败。

#### 2.2.7 独立桌面管理维护程序

##### 2.2.7.1 功能描述

**连接与管理：**

- 打开桌面程序 → 独立运行，不要求 AgentDDS 已启动；它不是网页，也不嵌入后台。
- 默认连接本机 IP，也可输入其他主机 IP。连接失败 → 显示不可连接，不报就绪。
- 连接本机或远端 → 查看该实例的模型、技能和当前会话连接状态；可调试功能、查看结果或任务状态，不把本机能力当成远端能力，也不伪造成功。
- 主动结束所连实例的指定会话 → 按 §2.2.2 清理会话、记录和子任务，不影响其他会话。

**启动、关闭和重启的区别：**

| 操作 | 允许范围与条件 | 结果 |
| --- | --- | --- |
| 启动 | 实例未运行或已整体关闭，由本机发起；远端不能启动 | 桌面可从默认安装目录定位并启动，待就绪后连接，不依赖已退出的管理入口 |
| 关闭 | 仅本机操作，远端不能关闭 | 工作端和启动端一起退出；普通调用与管理入口均不可连接，桌面仍独立运行 |
| 重启 | 本机或远端的运行中实例；已停止实例不能借远程重启启动 | 启动端保持运行，工作端重启；旧会话、执行状态和待处理请求失效，重新就绪后桌面恢复连接 |

- 默认目录只是桌面自动定位启动的前提；非默认目录不承诺自动定位或启动。
- 只有重启保留启动端。重启受理不等于成功；未能重新就绪 → 显示失败或不可用，不误报恢复连接。
- 自动查找开关仅本机宿主或同机桌面可改，规则见 §2.2.5；连接远端不能修改其本地配置。
- 远端可调试能力、管理会话及重启运行中实例，但不能启动、关闭或修改本机专属配置。第一版不做鉴权也不扩大这些范围。

##### 2.2.7.2 模块验收标准

- **后台停止时打开桌面**：打开桌面程序 → 独立运行，默认本机并显示未连接，不要求浏览器或网页。
- **切换目标 IP**：连接另一实例后查看、调试 → 操作的都是该实例的模型、技能和会话。
- **本机或远端结束会话**：查看所连实例当前会话连接状态，再结束其中一段 → 只清理其记录和子任务，其他会话仍可用。
- **本机整体关闭**：点击关闭 → 两端一起退出，普通与管理入口均不可连接；桌面仍运行。
- **关闭后本机启动**：默认目录安装的实例已整体关闭，同机桌面发起启动 → 从该目录启动，初始化完成后连接，不依赖已退出的管理入口。
- **本机与远端重启**：分别重启运行中的本机和远端实例 → 启动端保持运行；重新就绪后桌面恢复连接，旧会话和任务不恢复；相同窗口 GUID 的新请求只能创建全新上下文。
- **重启未完成**：重启已受理但未能重新就绪 → 显示失败或不可用，不显示已恢复连接。
- **停止状态与远程启停**：尝试远程操作停止实例 → 远程重启不使其启动；不提供远程启动、关闭或修改本地开关的操作。
- **第一版无鉴权**：局域网可连接方调用普通功能、调试、查看和结束会话或重启运行中实例 → 无需身份或管理凭据；本机专属操作仍不对远端开放。

## 3. 第一版范围边界

- 不开发设备自身业务，不把 AgentDDS 做成网页或桌面界面；管理使用独立桌面程序。
- 不承诺互联网访问，不做跨局域网聚合，也不要求实例长期维护全局能力清单。
- 普通调用、远程调试、会话管理和运行中实例重启均不做身份认证、授权、角色权限或白名单；这不开放远程启动、关闭或本机专属配置。
- 不因受理后失败自动换目标、重做或重发；多中转站不要求自动故障切换。
- 不规定子 Agent 的固定数量、内部调度或具体执行逻辑。
- 不提供长期历史保存、查询或管理；图片和视频模型本身不维护聊天历史；不跨重启恢复旧会话或任务，也不代调用方重发。
- 除 H3 兼容目标外，示例型号不是必选；以实际后端已核实操作为准，不照搬云端能力。视频真实调用留待后续，不把非真实验证报为真实验证通过。
